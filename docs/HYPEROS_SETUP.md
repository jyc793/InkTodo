# Redmi K70 至尊版 HyperOS 提醒可靠性配置

墨待不会绕过系统授权。首次启动不需要把所有权限一次开完；第一次真正创建强提醒或持续提醒时，再进入 App 内“提醒可靠性”页面逐项设置即可。

## 建议配置

### 1. 通知

- 系统设置 → 通知与状态栏 → 应用通知管理 → 墨待 → 允许通知。
- 允许锁屏通知与悬浮通知。
- 在墨待中分别查看四个必要渠道状态；任一项异常都可点击按钮直达该渠道设置。升级后的首次启动会清理旧版重复渠道。
- “持续任务常驻通知”应保持允许显示，但设计为无声；“持续任务开始提醒”负责开始时的一次声振。

### 2. 精确闹钟

- 在墨待“提醒可靠性”页点击“精确闹钟能力 → 去开启”。
- 允许该 App 设置闹钟和提醒。
- 返回 App 后状态会立即刷新，无需重启。

若不允许，墨待仍会用 Android 官方 `setAndAllowWhileIdle` 安排提醒，但系统可以延后触发，因此不属于同等可靠性。

### 3. 全屏强提醒

- 在“全屏强提醒”项点击“去开启”。
- Android 14+ 由系统决定是否允许该应用使用全屏提醒。
- 此权限主要负责锁屏状态打开独立确认页。Android 13+ 在手机已解锁并正在使用时固定显示 heads-up，而不会启动 Full Screen Activity。
- 确认页返回键不会结束提醒，只有点击“确认”才取消正式通知。
- “待确认提醒恢复”是无声通道，仅用于手机重启或 App 恢复后重新贴出尚未确认的正式通知，防止重复播放声音。

### 4. 页面上层确认框

- 在“页面上层确认框”项点击“去开启”，允许“显示在其他应用上层”。
- 这是手机解锁时到点直接覆盖桌面或当前 App 弹出确认框的必要权限；未授权时只能显示高优先级 heads-up，点击通知仍可进入确认页。
- 墨待只在用户设置的正式提醒到点后使用该窗口，点击确认立即移除；不使用 Accessibility、Root 或隐藏 API。

### 5. 自启动与后台

- 安全中心 → 应用管理/授权管理 → 自启动管理 → 开启墨待。
- 应用详情 → 省电策略/电量与性能 → 墨待 → 无限制。
- 允许后台活动，避免将墨待加入冻结或深度清理名单。

HyperOS 的页面路径会随版本改变。墨待优先尝试打开 `com.miui.securitycenter` 自启动管理；无法解析时自动退回本应用详情页。

### 6. 系统时钟

- 创建“某个时刻提醒”时可开启“使用系统闹钟”。
- 预提醒仍由墨待负责。
- 正式时间通过 `AlarmClock.ACTION_SET_ALARM` 交给 HyperOS 时钟。
- 墨待不会再同时播放自己的正式强提醒，避免双响和蓝牙音频焦点竞争。
- Android 官方 Intent 不能传具体年月日。墨待会先显示完整目标日期；进入系统时钟后必须人工核对日期/重复规则并保存。
- 若系统时钟无法打开，墨待会把该任务持久改回 App 正式强提醒作为备用。

## 使用时避免

- 不要对墨待执行“强行停止”。
- 不要关闭预提醒、正式强提醒、持续开始提醒或持续常驻通知渠道。
- 不要撤销精确闹钟后仍期待精确到点。
- 不要在安全中心把墨待加入休眠、冻结或自动清理列表。

## 状态仍显示异常时

1. 从系统设置返回墨待，等待“提醒可靠性”页自动刷新。
2. 检查对应通知渠道，而不仅是总通知开关。
3. 检查自启动、电池“无限制”和锁屏/悬浮通知。
4. 重新打开墨待，让恢复协调器校准未来提醒。
5. 若 HyperOS 更新后设置页路径改变，使用该项“去开启”的应用详情回退，并按页面说明人工确认。
6. 查看“最近提醒执行状态”；若出现失败，重新打开 App 会自动从 Room 校准并重试未来提醒。

## 蓝牙音乐验证

正式待办提醒使用系统默认通知音，非循环播放且最多 8 秒，不使用 Alarm 音频用途，也不会由墨待自行申请 Audio Focus。验证时请先用蓝牙耳机播放音乐，再分别测试预提醒、App 正式提醒、持续开始提醒和系统原生闹钟；前两类允许短暂压低音量，但音效结束或确认后音乐应自动恢复。
